# 怎么用公司账户买国内大模型？对公、专票、子账号全流程走查

## 先说个人充值和公司采购的区别

个人开发者买 API：注册 → 支付宝扫码 → 充值 → 拿 Key 就跑。全程十分钟。

公司采购不是这么回事。公司账户要解决的是：**钱怎么花得合规（对公/发票）、团队怎么用（多 Key 权限）、账怎么算（费用分摊/审计）**。这三件事，个人流程里一个都没有。

这篇走查公司账户买国产大模型 API 的完整流程：从企业认证开始，到月度对账结束，每一环该准备什么、该核对什么，都写清楚。

## 第一步：企业认证

公司采购的第一关是让平台知道"你是一家公司"。通常需要：

- **营业执照**：平台企业认证要上传，用于开票主体和合同主体；
- **企业信息**：公司全称、统一社会信用代码、开户行信息——后面开发票、对公转账都用得上；
- **认证时效**：有的平台认证要 1-3 个工作日，别等月底要发票了才想起来认证。

**核对点**：认证完立刻确认两件事——开票主体名称和营业执照一致、支持的对公收款账户信息完整。不一致的，后面每一张发票都是麻烦。

## 第二步：对公打款

对公打款比个人充值多几步：

1. **确认平台对公收款账户**（开户名、账号、开户行），和营业执照主体核对；
2. **公司网银打款**，用途栏写清楚（"API 服务费"之类），打款凭证留档；
3. **平台确认到账**，到账后余额入账——到账确认时效各平台不同，快的实时，慢的要看工作日；
4. **要求开票**：专票还是普票、什么时候开、最低金额，付款前就确认（完整核对清单见同系列《先拿专票再对公打款：企业采购大模型 API 的发票前置避坑指南》（repo: invoice-first-procurement-guide）篇）。

**核对点**：打款后 24 小时没到账的，直接找客服留工单记录。对公到账问题比个人充值纠纷难处理得多。

## 第三步：团队权限管理（子账号）

公司买 API 不是一个人用。团队场景下，"一个 Key 所有人共用"是灾难：谁在调、调了多少、超没超预算，全查不到。

正规做法是**子账号 + 限额**：

| 需求 | 个人模式 | 团队模式 |
|------|----------|----------|
| 多人使用 | 共用一个 Key | 每人独立子账号/Key |
| 权限控制 | 没有 | 按成员/项目分配额度 |
| 用量追踪 | 混在一起 | 按子账号统计 |
| 限额保护 | 无，敞口消费 | 可设上限，超限自动停 |

**核对点**：选平台时确认三件事——支持创建子账号吗？子账号能设用量上限吗？用量能按子账号/项目导出吗？三项缺任何一项，团队用起来都要靠人工对账。

## 第四步：费用分摊

多项目、多部门的公司，API 费用要摊到各自预算里。分摊的前提是"用量可归属"：

- **按子账号分摊**：每个项目一个子账号，月底按子账号汇总；
- **按模型分摊**：统计每个模型的花费，评估哪个模型值不值得继续用；
- **按时间/项目导出**：控制台能导出明细表格，财务才能做内部核算。

**核对点**：别等月底才发现"控制台只能看余额，看不到按模型的消费"。注册后先看控制台的统计功能，比充值后再后悔强。

## 第五步：审计与对账

财务月结时，API 采购的证据链要闭环：**对公回单 → 发票 → 用量明细 → 内部费用归属**。

- 对公回单：银行流水，证明钱付给了谁；
- 发票：专票/普票，抬头与打款主体一致；
- 用量明细：控制台导出，证明钱买了什么服务；
- 内部归属：按子账号/项目的分摊表，证明钱记在谁的账上。

四样东西齐全，报销、审计、税务都过得去。缺一样，财务就得追着你要材料。

## 官网直连 vs API 聚合平台

多模型混用的公司，逐个官网采购意味着把上面五步重复 N 遍——N 个对公账户、N 张发票、N 套子账号体系、N 份明细格式。聚合平台把多模型收敛成一套：

| 环节 | 官网逐个直连 | API 聚合平台 |
|------|-------------|-------------|
| 认证 | 每个平台各一次 | 一次 |
| 对公 | 每个平台各一次打款 | 一个账户统一充值 |
| 发票 | 每家一张，票种参差 | 统一开票 |
| 子账号 | 各家体系不同 | 一套体系管所有模型 |
| 明细 | 格式不一，人工汇总 | 一张表所有模型 |
| 对账 | 跨平台拼证据链 | 单平台完整导出 |

聚合平台的代价是引入一个中间层，所以采购前要把财务能力当一等需求核验：能不能开专票、对公收款账户是不是公司主体、明细能不能按子账号导出。以 Tokeness 为例（2026-08 核验）：模型广场公告明确"可对公发票，长期稳定；仅转发，不保留任何对话数据"，一个 Key 调用全部模型，控制台有按模型的用量记录——这些在付款前就能从公开页面确认。

## 月度例行动作

采购不是一次性的事。把下面四项设为每月固定动作，问题会在变大之前暴露：

1. **月初对价格**：模型价格和折扣会变（2026 年 8 月 DeepSeek 就涨过一次），月初过一遍定价页，预算偏差大的及时调；
2. **月中看用量**：按子账号/模型拉一次消费，超预算的项目提前干预，别等月底；
3. **月底开票对账**：当月消费申请开票，用对公回单、发票、明细三件套做一次闭环核对；
4. **季度审平台**：是否还满足专票、对公、明细导出三项要求，不满足就尽早切换，别被存量余额绑住。

## 结论

公司账户买大模型，核心不是"充多少钱"，而是**合规、权限、分摊、审计**四件事有没有着落：企业认证对好主体、对公打款留好凭证、子账号设好限额、月底能导出明细分摊。把这五步走查一遍，不管直连官网还是走聚合平台，都能回答财务的任何一个问题。

# 先拿专票再对公打款：企业采购大模型 API 的发票前置避坑指南

## 先说一个"充值一时爽"的案例

有个朋友的公司要做 AI 客服，他看中一家中转站价格便宜，当天就充值了 2000 元。月底要发票，客服说"个人充值渠道开不了公司抬头发票，专票要企业认证后走对公"。

他走对公流程，对方又说"对公要满 5000 元起"——为了一张发票，卡在一个不存在的门槛上。钱已经充进去了，只能硬着头皮继续用。

企业采购 API，**发票和付款方式必须在充值前确认**，这就是"发票前置"：先确认能开票、能对公、明细可查，再付款。这篇给一份可执行的核验清单。

## 付款前必须确认的 7 件事

拿着这份清单，给候选平台逐个问一遍（能查到正式说明的，以公开页面为准）：

| # | 核验项 | 问什么 | 为什么重要 |
|---|--------|--------|-----------|
| 1 | 开票资质 | 能开增值税专用发票吗？还是只有普票？ | 专票可抵扣进项税，大额采购标配 |
| 2 | 开票主体 | 发票抬头能开公司名+税号吗？ | 个人抬头发票公司没法报销 |
| 3 | 付款主体 | 支持公司对公转账吗？ | 个人收款码开不出公司发票 |
| 4 | 开票周期 | 充值后多久能开票？当月还是次月？ | 财务月结时间表要靠这个排 |
| 5 | 起开金额 | 有没有最低开票金额？ | 案例里 2000 元就卡在"满 5000 起" |
| 6 | 用量明细 | 控制台能导出每笔调用明细吗（时间/模型/tokens/金额）？ | 报销和审计的证据链 |
| 7 | 退款规则 | 余额可以退吗？退款开票怎么处理？ | 换平台时的善后成本 |

前 4 项决定"能不能报销"，后 3 项决定"报销顺不顺"。任何一项在公开页面查不到、客服给不出明确答复的，都按"不支持"处理，别用"应该可以"安慰自己。

## 先票后款，还是先款后票？

企业采购 API 有四种典型节奏，差异很大：

| 节奏 | 流程 | 适合谁 |
|------|------|--------|
| 先充值后开票 | 个人/对公充值 → 月底开票 | 中小团队默认方式 |
| 对公打款后开票 | 对公转账 → 确认到账 → 开票 | 大多数对公场景 |
| 先开票后打款 | 平台先开票 → 公司凭票打款 | 供应商信用较好的企业级合作 |
| 合同+月结 | 签合同、按月结算 | 大客户、长期采购 |

"先开票后打款"听起来对采购方最友好，但要求平台愿意承担先票后款的风险，通常只给企业认证客户。小团队别指望，直接按"对公打款后开票"规划流程即可。

## 五个常见坑

**坑 1：个人充值渠道开不了公司发票。** 支付宝/微信个人付款，平台很难开出公司抬头发票。付款前确认"这个充值入口能不能开公司发票"。

**坑 2：说"能开票"实际是普票。** 财务要专票，平台只能开普票，抵扣不了进项税。把"专票"两个字问出口，答复含糊的按普票处理。

**坑 3：发票拖延。** 宣传"可开票"，实际要催两个月。开票周期在付款前确认，写进聊天记录。

**坑 4：明细导出缺失。** 发票能开，但控制台只有余额没有逐笔明细。报销时财务问"这 3000 元干了什么"，答不上来。付款前看一眼控制台有没有调用日志和导出。

**坑 5：退款等于没有。** 余额不能退、或退款要扣手续费。小额测试阶段先充最小金额，验证发票、明细、稳定性都符合预期，再放大用量。

## 客服话术模板：别问"能开票吗"

同样一个问题，问法和答法都影响结果。把七项核验拆成具体问题，按这个模板问（邮件或工单，留记录）：

```
1. 贵平台支持开具增值税专用发票吗？开票主体是平台主体还是第三方？
2. 公司对公转账的收款账户信息是什么？个人充值渠道开的发票能否开公司抬头？
3. 充值后多久可以申请开票？当月还是次月？有没有最低开票金额？
4. 控制台支持导出逐笔调用明细吗（时间、模型、tokens、金额）？
5. 余额支持退款吗？退款规则是什么？已开发票如何红冲或换开？
```

五个问题全部有明确文字答复的，截图存档。答复含糊、回避、"找销售单独聊"的，按扣分处理——不是说不合作，而是这类平台出问题时的沟通成本通常也高。

## 小额测试流程：把核验闭环走一遍

正式采购前，用最小充值金额把"付款 → 开票 → 明细 → 退款"完整走一遍：

1. **充值最小金额**（能支持测试的量级，别一上来就冲大额）；
2. **跑真实任务**：调几个模型，确认控制台出现逐笔调用记录；
3. **申请开票**：走一遍开票流程，确认票种（专票/普票）、抬头、到账时间；
4. **测试退款**：确认余额可退、规则清晰——这一步很多人跳过，恰恰是最容易出问题的环节。

一套流程走完，平台适不适合长期用基本就有数了。适合的再谈对公、再谈放大用量；不适合的，损失也只有最小充值金额。

## 聚合平台的财务能力怎么从公开页面判断

不需要全部问客服，三处公开信息基本能看出平台的财务成熟度：

1. **模型广场/公告**：是否写"可对公发票""支持专票"这类财务条款。以 [Tokeness](https://tokeness.ai/) 为例，模型广场公告明确写"可对公发票，长期稳定；仅转发，不保留任何对话数据"，这类公开声明比客服口头承诺可靠；
2. **文档**：有没有开票、对公、退款的正式说明页（没有说明页，至少要有常见问题）；
3. **控制台**：有没有充值记录、调用明细、按项目/日期导出——注册后不用充值就能看到界面。

顺序是：先看公告和文档，再注册看控制台，最后小额充值实测。把"能开专票、能对公、明细可查"三项验证完，再考虑放大用量。

## 结论

企业买大模型 API，"能开票"和"能报销"是两回事。发票前置的意思，是**在付款之前**把专票资质、对公收款、开票周期、明细导出、退款规则五项确认清楚，而不是充值之后再去补。

核验清单背下来：专票？公司抬头？对公？多久开票？明细能导出吗？余额能退吗？——七问七答，能过的平台不多，但过不了的，大概率就是会给你报销添堵的。
